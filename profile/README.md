<h2>一、五类场景，配置不该一样</h2>
<p>先对号入座，看清自己属于哪一类。选错类型，后面的钱基本白花。</p>
<h3>内容与文案生产</h3>
<p>特点是单次会话长、上传文档多、对带宽敏感。配置建议：每号一条独享家宽，城市固定，上行不低于 5 Mbps。关键指标是会话中断率，超过 2% 就该查线路抖动。</p>
<h3>跨境客服值班</h3>
<p>特点是分班次、多人共用账号、登录时间集中在早晚交接。配置建议：账号绑线路，人不绑线路，交接时只换人。关键指标是交接后 48 小时内的验证次数。</p>
<h3>自动化与批量任务</h3>
<p>特点是请求密集、失败重试多。配置建议：一号一出口加备用线路，并发单独核算。关键指标是 429 占比与 p95 延迟。</p>

<h2>二、按账号分配出口的三种做法</h2>
<p>「一号一环境」说起来简单，落地时有三种粒度，成本和隔离效果都不同。</p>
<h3>做法一：一号一地址</h3>
<p>最彻底，每个号独占一个 IP。成本最高，但同段牵连的概率最低。适合单号价值高、账号数量在几十以内的团队。</p>
<h3>做法二：一号一地址段</h3>
<p>每个号占一个 /29 小段里的一个地址，同段的其他地址不分配给别的号。成本比一址略低，隔离效果接近，适合五十到两百号规模。</p>
<h3>做法三：分组共享池</h3>
<p>按项目或城市分组，组内共享一个地址池，但组与组之间不交叉。成本最低，代价是组内仍有少量共用。适合内部测试、短期验证这类对隔离要求不高的场景。</p>
<h3>三种怎么选</h3>
<p>看两个维度：单号的历史价值、组内可接受的牵连范围。账号养了三个月以上、有对话历史，值得上一号一地址；只是跑通流程的测试号，分组池足够。</p>
<p>成本差多少也值得算一笔。以三十个号为例，一号一地址的出口月支出约在两千四到七千元，一号一段略低一成左右，分组共享池通常只要前者的三到四成，仅供参考。差价换来的是风险边界，值不值取决于单号被牵连一次的损失有多大。</p>

<h3>哪一层最容易被省掉</h3>
<p>系统层。出口在美国、系统时区还留着东八区，语言是 zh-CN，这种组合在后台看来非常突兀。改时区只要十秒，但很多团队从没改过。</p>
<h3>隔离过度的浪费</h3>
<p>另一种浪费是给每号配独立虚拟机、独立网络命名空间，成本翻三倍，收益却很有限。多数场景下，配置文件隔离加独立出口已经足够，虚拟机只在需要完全隔离测试时才用。</p>

<h2>四、扩区与缩容怎么迁移</h2>
<h3>开新地区市场的步骤</h3>
<p>四步：先买两三条当地住宅线做小流量验证；验证通过后按批次开号，同批同城；老号不迁，新号另立批次；观察两周再把预算挪过去。老号迁区是成本最高、收益最低的动作，能不做就不做。</p>
<h3>缩容时先停哪一类</h3>
<p>顺序是：临时按小时的线 → 分组共享池 → 独享但闲置超过一个月的线 → 主力号。前两类停了不影响主力环境，最后一类要留到确认业务量下降之后再动。</p>
<h3>迁移期的记录要求</h3>
<p>每批新号单独一张表，记清楚开号日期、当地出口、负责人。迁移期最容易出现的问题是新老号混在同一份台账里，出事后分不清哪批用的是哪条线。</p>
<h2>常见问答</h2>
<h3>五个号需要几条线路？</h3>
<p>答：按账号数配，五个号五条线，不要按人数配。人少可以错峰，账号的登录地却不能随便变。</p>
<h3>分组共享池会不会影响账号？</h3>
<p>答：组内共用意味着组内成员的行为会互相影响，风险不会归零。只建议用在测试号或短期验证上，正式号还是独享。</p>
<h3>客服三班倒，交接时要不要换线路？</h3>
<p>答：不要。线路跟着账号走，人换线不换，这样每次登录地都一致。换人只换操作者，环境保持不变。</p>
<h3>演示用临时号怎么配最省？</h3>
<p>答：按小时租一到两条本地住宅线，演示前一小时开通并跑通一遍，结束后停掉。比包月省，也比临时借别人的环境稳。</p>
